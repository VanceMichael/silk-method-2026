# 采集台：分项收料与交付

采集台面向质检员，把“业务资料来源”（订单、绑定、测试、证书范围、等效、签发与改签）和
“实验室原件来源”（清单、页件、买家回执）汇合成可重复办理的分项状态。纯 Node.js 内置模块，
无第三方依赖。

## 启动

三个进程分别对应业务来源、原件来源和采集台：

```sh
npm run source      # http://127.0.0.1:8700
npm run provider    # http://127.0.0.1:8701
npm run station     # http://127.0.0.1:8702
```

采集台可用 `STATION_PORT`、`STATION_DIR`（默认 `./station-data`）、`SOURCE_ROOT`、
`PROVIDER_ROOT` 调整。状态写入 `STATION_DIR/state.json`，页件按 sha256 内容寻址存入
`STATION_DIR/pages/`，重启后全部签收、缺项与历史清单代仍然保留。

## 办理规则如何落地

| 业务要求 | 采集台做法 |
| --- | --- |
| 先索引摘要、再页件清单，总目录可能晚更新 | `POST /sync` 每次先拉 `/catalog` 再按流分页拉取；ETag 只在同一资料版内复用，换版整轮重取 |
| 按底稿和页件版本收原件，每页核实完整性 | 清单成员逐个按 `sha256` 取页；不符记 `mismatch`，取不到（如 425）记 `missing`，均不入库为有效页 |
| 同档案号也不能用旧页充当新证明 | 页件状态按“清单代 + path + sha256”绑定；换代后旧代页件只留在 `history/observations` 供旧回执追溯 |
| 坏页可单独领、缺一页只影响相关指标 | 成员级状态独立；判定按指标汇总，缺项见 `/missing`，并列出受影响订单 |
| 两份订单允许时共用实际原件 | 页件只按内容寻址存一份；两个订单的 `usable.page.stored` 指向同一文件 |
| 样品朝向以接收单为准、跨实验室不混用 | 候选必须匹配同实验室、接收单、本地样品号与订单朝向；同号样品在不同实验室的绑定分别落点 |
| 单位按实验室公布换算 | 页件 `厘牛` 按 0.01 换算为 `牛` 后与测试摘要交叉核对（`crossCheck`） |
| 等效有方向、限买家/条件/适用日 | `equiv` 建成有向边，按买家、条件和左闭右开适用日做 BFS，给出完整方法链 |
| 改签只替换一个指标 | `corrected` 以“旧报告+指标”为键替换，同报告其他指标仍按原记录判定 |
| 旧回执可追溯、失效要追查买家 | `/receipts` 保留签收；`/corrections` 列出受影响订单；失效项进入 `review` 并移出可再发列表 |
| 先停用旧凭据才能接新件 | `POST /withdraw` 记 `pending`；该期间 `/deliver` 本地直接 409，provider 确认 `withdrawn` 后放行 |
| 反面缺项落到实际接收单和页版 | `/missing` 给出实验室、接收单、样品、朝向、清单代与期望摘要 |

## HTTP 接口

- `POST /sync`，体 `{ "packs": ["K1"] }`：同步业务流、指定原件包与买家回执。
- `GET /orders`：每张订单按指标给出状态。
  - `ready` 有核实原件可交；`pending-supply` 纸质依据成立但缺原件；
    `no-basis` 条件/方法/朝向不成立；`review` 旧凭据待停用复核；`delivered` 已签收且依据仍成立。
  - 每项含候选报告、方法链、绑定接收单、原件 path/sha 与具体 `blockers`。
- `GET /missing`：缺页/坏页落点（接收单、朝向、清单代、期望 sha、受影响订单）。
- `GET /packs`：包的清单代、成员核实状态与历次观察。
- `GET /receipts`：买家回执实况叠加本地停用申请。
- `GET /corrections`：改签映射与用到旧报告的买家追查。
- `POST /withdraw`，体 `{ order, item, receipt }`：申请停用旧凭据。
- `POST /deliver`，体 `{ order, item }`：本地复核通过后按清单代和成员校验值提交；
  同一“订单+指标+清单代+sha”重复办理直接返回原回执，不重复发件。
- `GET /deliveries`、`GET /syncs`、`GET /pages/{sha256}`：交付记录、同步记录与内容寻址页件。

## 测试

`npm test` 会在临时端口启动两个来源和采集台，覆盖 r1 收料、corrected 清单先换代而原件迟到、
withdrawn 共用原件与交付、改签单指标替换、跨实验室样品隔离、分页/ETag 与重启持久化。
